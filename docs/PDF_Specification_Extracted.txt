should be four members.   
Project Specification     
  
The purpose of this assignment is to create an end-to-end Smart Solar Microgrid Trading 
System using client-server architecture. The system features a web application for back-
office administration and microgrid site operators, alongside a mobile applicati on for 
solar prosumers (property owners with solar panel arrays). 
 
a) Web Application: 
• User Management:  Create web application users with two distinct roles: 
Backoffice and Grid Operator. Only Backoffice users have access to system 
administration functions, while Grid Operators access operational tools.  
 

=== PAGE 2 ===
 
 
   
 
• Prosumer Management: Create, update, and deactivate prosumer profiles 
using National Identity Card (NIC) as the primary key. Deactivated accounts 
can only be reactivated by a Backoffice officer.  
• Microgrid Node Management:  Manage solar grid hubs, including creating 
new hubs with GPS location, capacity specs (kW/h), and available battery 
storage slots. Update schedules and deactivate nodes (deactivation is 
blocked if active energy reservations exist).  
• Energy Slot Reservation Management:  Create, update, and cancel power 
trading reservations (must be scheduled within 7 days; updates and 
cancellations require at least 12 hours' notice).  
• User Interface: Developed using Bootstrap 5, Tailwind CSS, or React.js for a 
responsive appearance. 
b) Mobile Application: Mobile apps must be pure Android with SQLite DB (no 
frameworks) 
• Mobile applications are intended to provide functionalities for both Solar 
Prosumer and grid operators. 
• Native Specs:  Pure native Android with local SQLite database for local 
user management (no cross-platform frameworks allowed).  
• Prosumer Account Control: Prosumers register using NIC as the primary 
key, edit profile data, and request account deactivation.  
 
• Reservation & QR Dispatch: Prosumers reserve, modify, or cancel energy 
drop-off/charging slots. Once approved, the app generates a secure 
transaction QR code.  
 
• Dashboard & Maps: Display active/pending reservation counts, Bookings, 
and nearby grid nodes via Google Maps API. Additionally, user should be 
able to view booking history, pending booking and search booking 
 
• Operator Mode:  Grid Operators log into the mobile app, scan the 
prosumer's transaction QR code, verify server data, and finalize energy 
transfer business logic.  
 
c) Web Service 
• Architecture: FAT Service pattern where all business logic resides strictly in 
the central API.  
• Tech Stack: C# Web API deployed on Windows IIS Server with a NoSQL server-
side database (e.g., MongoDB).

• Client Constraints: Both Web and Pure Android clients act as UI interfaces,

This system incorporates web and mobile applications that connect to a centralized

Project Scenario: 
In this project scenario, the Backoffice team is responsible for managing the 
registration of solar microgrid nodes and maintaining their operational schedules. 
Grid operators, who can access both the web application and the mobile application, 
are respons ible for updating battery slot availability and monitoring power trading 
bookings. Solar prosumers, on the other hand, can conveniently use the mobile 
application to reserve energy slots, modify existing reservations, and review their 
energy transfer histo ry. Once a booking is confirmed, the prosumer receives a 
confirmation and can access the details directly on their dashboard. If circumstances
